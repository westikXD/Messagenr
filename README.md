# Простой мессенджер (текст + фото + аудио/видео звонки)

Стек: **Node.js + Express + Socket.io** (бэкенд) и **HTML/CSS/JS** (фронтенд),
звонки — через **WebRTC** (сигнализация идёт через Socket.io).

## Структура проекта

```
messenger/
├── server.js          # сервер: раздача статики + Socket.io (чат и сигнализация)
├── package.json
└── public/
    ├── index.html     # разметка интерфейса
    ├── style.css      # стили
    └── client.js      # логика клиента: чат, фото, WebRTC
```

## Как запустить

1. Убедитесь, что установлен Node.js (версия 16+).
2. В папке проекта выполните:
   ```bash
   npm install
   npm start
   ```
3. Откройте в браузере **http://localhost:3000** — это будет первый пользователь.
4. Откройте ещё одну вкладку (или другое устройство в той же сети,
   заменив `localhost` на IP-адрес компьютера) — это второй пользователь.
5. Войдите под разными никами, выберите собеседника в списке слева —
   можно переписываться, отправлять фото и звонить (кнопки 📞 / 🎥).

## Как это работает

- **Чат**: клиент отправляет сообщение через Socket.io на сервер (`private-message`),
  сервер находит сокет получателя по нику и пересылает сообщение только ему.
  История чатов хранится в памяти браузера (переменная `chatHistories`), на сервере
  сообщения нигде не сохраняются — это простая демонстрационная реализация.
- **Фото**: файл читается в браузере через `FileReader` и превращается в
  base64 data-URL, который передаётся как обычное текстовое поле сообщения.
  Для реального продакшена лучше загружать файлы на сервер (например, через
  `multer`) и передавать в сообщении только ссылку — это заметно снизит трафик.
- **Звонки (WebRTC)**: браузеры сами устанавливают P2P-соединение для передачи
  аудио/видео, а Socket.io используется только чтобы передать друг другу
  служебные данные — `offer`/`answer` (SDP) и ICE-кандидатов. Для обхода NAT
  используется публичный STUN-сервер Google. Если оба пользователя находятся
  за "сложным" NAT/файрволом, для надёжной работы может понадобиться ещё и
  TURN-сервер (в демо не включён).

## Известные ограничения (упрощения для демо)

- Нет базы данных: список пользователей и история чатов живут только пока
  запущен сервер / открыта вкладка браузера.
- Один звонок одновременно на пользователя (нет очереди звонков).
- Нет TURN-сервера — в редких сетевых конфигурациях P2P-соединение для
  звонка может не установиться.
- Ники не защищены паролем — это просто идентификатор сессии.

Всё это можно доработать: добавить БД (PostgreSQL/MongoDB), аутентификацию
с паролями, загрузку файлов на сервер, TURN-сервер (например, coturn) и т.д.
